## 2026-09-12 — T-035 [Architect]
Decided: SSE event schema is snake_case
`{timestamp, run_id, iteration, phase, node, event, duration_ms, output_summary}`
(execution.jsonl's schema minus tokens_in/tokens_out/model), event ∈ {start, end} only (no
error frame). graph.invoke runs via asyncio.to_thread (T-034 decision 2), so every
EventEmitter hook fires on a worker thread; all enqueueing goes through
loop.call_soon_threadsafe(put_event_dropping_oldest, queue, event), never a bare
put_nowait — the emitter captures its owning loop via asyncio.get_running_loop() at
construction time, inside create_run/resume_run on the event-loop thread. The per-run queue
(maxsize=1000, drop-oldest on full, never raises QueueFull into a callback hook) lives on
app.state.event_queues: dict[str, asyncio.Queue], created synchronously in create_run/
resume_run alongside JsonlCallbackHandler (before asyncio.create_task), and removed from the
dict once the SSE generator in events.py consumes the terminal STREAM_END sentinel — emitted
from _run_and_track's finally block on all three outcomes (completed/interrupted/failed).
resume_run always creates a fresh queue rather than reusing a stale one; a client still
streaming the old queue object across a resume will not see the new run's events (accepted:
SSE is an explicitly lossy live view, not a durable channel). EventEmitter
(src/api/event_emitter.py) is a new BaseCallbackHandler that independently reimplements
JsonlCallbackHandler's node/phase-identification logic rather than subclassing it or calling
its private members, since src/observability/ is infra-agent's folder.
Why: correctness under FastAPI's asyncio.to_thread execution model (a bare put_nowait from a
non-owning thread is unsafe on asyncio.Queue and fails silently, undetected by a same-thread
unit test); keeping the SSE stream explicitly lossy while execution.jsonl stays the durable
record; avoiding a private-API dependency across an agent ownership boundary.
Affects: src/api/event_emitter.py (new), src/api/routers/events.py (new),
src/api/routers/runs.py (_build_config generalized to multiple callbacks; _run_and_track/
_resume_and_track thread an event_queue param and emit the terminal sentinel in a finally
block), src/api/main.py (app.state.event_queues).

## 2026-09-12 — T-035 [Coder]
Decided: Starlette's `TestClient` (0.37.2, the version pinned in this project) runs the whole
ASGI call synchronously inside `portal.call(...)` and only returns to httpx once the response
is fully buffered (`starlette.testclient._TestClientTransport.handle_request`) — confirmed by
reading the installed library source after `client.stream(...)` + early context-manager exit
hung indefinitely in two tests. There is no true incremental/partial read available through
it, even via `client.stream(...)`. The client-disconnect and heartbeat tests in
`tests/unit/api/test_events.py` therefore drive `events._event_stream` directly (an async
generator, run via `asyncio.run(...)`) with a minimal fake `Request` object exposing `.app`
and an `is_disconnected()` that flips to `True` after N calls, instead of going through
`TestClient`. Every other `test_events.py` test still exercises the full HTTP stack via
`client.get(...)`, which only needs the fully-buffered body and works fine.
Why: matches the plan's intent (verify disconnect stops the generator without raising, and
that a heartbeat is sent while idle) at the precise unit boundary that actually owns that
behavior, without depending on TestClient internals the installed version doesn't support.
Affects: tests/unit/api/test_events.py only — no production code behavior changed.
