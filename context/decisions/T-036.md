## 2026-09-12 — T-036 [Architect]

Decided: APPROVED WITH MODIFICATIONS. Seven binding conditions for the WebSocket
chat + explainer (see ADR 0002 for the explainer's shape).

1. **The explainer is not an `LLMNode` and need not be a `StateGraph`** — plain
   class in `src/api/explainer.py`, model + prompt from
   `config/agents/explainer.yaml` (`model_role: reasoning`,
   `output_file_pattern: ""`) and `config/prompts/explainer/v1.md`.
2. **`folders:` extended** to `["src/api/", "config/agents/explainer.yaml",
   "config/prompts/explainer/", "docs/api.md"]` — new leaf files only.
3. **Nothing on the WS path touches the checkpoint from the event loop.**
   `graph.get_state` acquires `SqliteSaver`'s `threading.Lock`, shared with the
   in-flight `asyncio.to_thread(graph.invoke, ...)` of an active run, so a read
   during a checkpoint write blocks its caller. Every checkpoint read goes
   through `await asyncio.to_thread(graph.get_state, config)`, as
   `routers/runs.py` already does; same for `WorkspaceManager` reads.
4. **No `websocket.send_*` from a worker thread** (L-014, the WS analogue of
   T-035's `put_nowait` hazard). Use `ainvoke`/`astream` on the event loop for
   the LLM; anything driven from a thread returns via
   `asyncio.run_coroutine_threadsafe` / `loop.call_soon_threadsafe`.
5. **Resume is shared code, not reimplemented.** Extract the body of
   `resume_run` into one helper in `src/api/` raising a domain error; REST maps
   it to `HTTPException`, the chat router to an error frame. The helper keeps
   the guard → `create_task` → `active_runs[run_id] = task` sequence
   await-free, so the chat path inherits T-034's TOCTOU fix.
6. **Approve and redirect are one code path** — both write `human_feedback`
   (empty/approval text vs. corrective text) and resume forward. No re-run of
   the completed phase.
7. **The explainer never writes `LabState`**, including `messages`. Chat turns
   live in the socket handler's local list only; `update_state` is reachable
   solely through the resume helper.

Why: `LLMNode.__call__` writes to the workspace and emits a `messages` delta —
both violate the read-only requirement, and the `messages` delta would collide
with the `add_messages` channel of a concurrently running graph. Conditions 3
and 4 come from the checkpointer being a single `sqlite3` connection with
`check_same_thread=False` shared across the event loop and the pipeline worker
thread. Condition 5 prevents a second, divergent copy of T-034 decision 4.

Affects: `src/api/explainer.py`, `src/api/routers/chat.py`,
`src/api/routers/runs.py` (resume extraction), `config/agents/explainer.yaml`,
`config/prompts/explainer/v1.md`, `docs/api.md` § WebSocket, `docs/adr/0002`.

Discarded: (a) subclassing `LLMNode` — writes files, mutates `messages`,
needs a meaningless `output_file_pattern`; (b) a one-node `StateGraph` — pulls
LangGraph construction into `src/api/`, breaking the fake-graph test seam for
zero benefit; (c) adding an optional field to `AgentConfig` so
`output_file_pattern` could be omitted — `src/config/schema.py` is a protected
contract and one non-writing consumer does not justify widening it;
(d) calling `resume_run` directly from the WS handler — it takes a `Request`
and raises `HTTPException`, neither of which belongs on a WebSocket.
