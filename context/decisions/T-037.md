## 2026-09-13 — T-037 [Architect]

Decided: APPROVED with conditions. Six rulings on the Kaggle submit + MLflow URL
endpoints.
Why: see each item.
Affects: src/api/routers/kaggle.py (new), src/api/routers/mlflow.py (new),
src/api/main.py (create_app gains an `mlflow_url` seam + two include_router lines),
src/api/models.py, docs/api.md, design.md (§ UI architecture endpoint table,
corrected by the Architect in this task), frontend/src/api/{client,types}.ts
(via discovery, not edited here).

1. **`GET /api/mlflow/url` is correct; `design.md:549`'s `POST /api/mlflow/open`
   is stale and is corrected in this task.**
   Why: `mlflow` runs as an always-on container (design.md:661-671). Spawning a
   second `mlflow ui` subprocess from the API container would bind a server with no
   `mlruns` volume and no published port — unreachable from the browser and
   duplicating a healthy service — and would add a subprocess-spawning endpoint to
   an API that has no authentication by design (design.md:212). plan.md:87 already
   agrees with the task file. No live consumer exists, so this corrects a
   never-implemented line rather than breaking a contract.
   docs/api.md: replace the `POST /api/mlflow/open` row with `GET /api/mlflow/url`,
   document both endpoints' schemas and error codes, and delete the "request/response
   schemas are not yet finalized" footnote — after this task they are.
   Discarded: keeping `POST` for symmetry with the frontend's guess (enshrines a
   side-effect verb on a pure lookup).

2. **The MLflow URL returned is the browser-reachable one, NOT
   `workspace.mlflow_tracking_uri`.**
   Why: that setting is `http://mlflow:5000` — a compose service hostname resolvable
   only inside the compose network. The endpoint's only consumer is the ActionBar
   button, which opens the URL in the user's browser on the host, where `mlflow` does
   not resolve. Returning it satisfies the "Done when" literally while shipping a
   button that is broken in the only supported deployment. The host-facing address is
   `http://localhost:5000` (design.md:610, `ports: ["5000:5000"]`).
   Mechanism: `create_app(mlflow_url: str | None = None)` → `app.state.mlflow_url`,
   resolved once at app construction as `mlflow_url` → `MLFLOW_PUBLIC_URL` env var →
   `http://localhost:5000`. This is the same injection seam as `runs_dir`/
   `graph_factory`.
   Discarded: adding a `workspace.mlflow_public_url` field to `WorkspaceConfig` — the
   cleaner long-term home, but it is a protected-contract change to
   `src/config/settings.py` + `config/settings.yaml`, both in infra-agent's folders.
   Escalated as a follow-up rather than done here.

3. **The endpoint never calls `Settings.load()` at request time.**
   Why: `Settings.load()` requires `api_keys.anthropic/deepseek/groq/kaggle_username/
   kaggle_key` to all resolve (src/config/settings.py:172-187) or it raises
   `ConfigError`. Making a URL lookup depend on five unrelated LLM API keys means the
   endpoint 500s in any environment missing one — including `tests/unit/api/`, whose
   conftest builds the app with no settings dependency at all. It would also re-read
   and re-parse the YAML on every request. Ruling 2's `app.state` seam removes the
   dependency entirely; tests pass an explicit `mlflow_url` and assert it round-trips.

4. **The submission file is located from the live checkpoint, not from
   `reports/kaggle_submission.json`.**
   Read `best_experiment_path` via the `_live_values` / `graph.get_state` pattern
   already in `runs.py`, take its basename through
   `WorkspaceManager.experiment_dir(name)` (honoring invariant #2 — the route
   src/nodes/compute/kaggle_client.py:80-88 documents as sanctioned for handing an
   absolute path to the Kaggle API), and append `submission.csv`. `competition_name`
   and `workspace_path` come from the run registry record.
   Why: `reports/kaggle_submission.json` records the outcome of a *prior automated*
   Phase 7 submission — it answers "did we submit and what did we score", not "which
   file do I send now". The T-033 discovery naming "an API endpoint" as its consumer
   refers to a future status endpoint, not this one. Recorded explicitly so the next
   reader does not wire the wrong source.
   No fallback to `experiments/exp_{current_iteration - 1}/submission.csv`: the
   Phase 7 node degrades silently and needs a best guess, whereas a user-triggered
   button must be predictable — absent file means a clear 409, not a surprise
   submission of a different experiment. The divergence is documented in docs/api.md.

5. **409 means "this run has nothing submittable", with three distinct messages;
   other failures are not 409.**
   - 404 — `run_id` absent from the registry (`RunNotFoundError`, matching runs.py).
   - 409 — (a) no checkpoint yet or `best_experiment_path == ""` (its `new_state`
     seed, src/state.py:82): "run has no best experiment yet"; (b) resolved path
     exists but `submission.csv` is not on disk: message **must name the exact path
     checked** — per the open T-033 discovery this is the common path today, since
     `coder` (T-029) does not yet write `submission.csv`; (c) `competition_name` is
     not a valid Kaggle slug (`ValueError` from `_validate_competition`).
   - 503 — `RuntimeError` from `_default_api()`: Kaggle credentials not configured
     on the server. A server-config fault, not a client one.
   - 502 — any other exception from the `kaggle` SDK (HTTP/API errors). Deliberately
     broad, same boundary reasoning as src/nodes/compute/kaggle_client.py:456.
   Why: `ValueError` = bad slug and `RuntimeError` = missing credentials are genuinely
   distinct (spec.md:247 conflates them and is wrong — the code, and the Phase 7 node
   at lines 432/444, separate them). Flagged for /refine.

6. **`public_score` is nullable, and `get_score` is wrapped.**
   Response: `{public_score: float | null, submission_file: str, message: str | null}`,
   snake_case, `submission_file` in workspace-relative form.
   Why: `kaggle_client.get_score` does an unguarded `float(latest.public_score)`, and
   src/nodes/compute/kaggle_client.py:495-498 already documents that an unset
   `public_score` is "the **normal** state in the seconds-to-minutes window right after
   `competition_submit`" — exactly this endpoint's call pattern. A required-float
   contract therefore 500s on the normal path, and a mocked tool returning a ready
   float would never reveal it. Catch `TypeError` first and specifically (it covers
   both the pending score and the open T-007 `date=None` failure mode this discovery
   names T-037 for), then broadly; on either, return HTTP 200 with
   `public_score: null` and a `message` explaining that Kaggle accepted the submission
   but has not scored it yet. The submission succeeded — that is not an error response.
   Must be asserted by a test that mocks `get_score` raising `TypeError`.

7. **Both Kaggle calls go through `asyncio.to_thread`.**
   Why: inherits T-034 decision 2. `submit` and `get_score` are synchronous HTTPS
   calls; awaiting an upload on the event loop freezes every other endpoint —
   including an active run's SSE stream — for its duration, violating design.md's
   Latency/Availability NFRs. Retrospective L-012: the mocked-tool tests in the
   "Done when" cannot detect this.
   Module-scope `import src.tools.kaggle_client` in the router is safe and should not
   be flagged by review: that module's docstring guarantees `kaggle` is never imported
   at module scope, so importing it never authenticates.

8. **The node's private helpers are not imported.** `_resolve_submission` and
   `_read_leaderboard_score` live in `src/nodes/compute/` (pipeline-agent's folder).
   Reimplement the thin parts needed inside `src/api/`, and log a discovery proposing
   promotion to a shared public helper — same boundary and same remedy as T-035's
   EventEmitter vs JsonlCallbackHandler ruling.
