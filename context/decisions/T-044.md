## 2026-09-13 — T-044 [Architect]
Decided: Drop the Chroma service container from T-044's scope.
Why: No test in the repo connects to a Chroma server. `tests/tools/test_rag.py` runs
against `chromadb.EphemeralClient()` (in-memory, documented in its own module docstring);
`src/memory/store.py:74 build_client()` returns `EphemeralClient()` unless BOTH host and
port are passed, and only `src/nodes/llm/*` pass them, from
`Settings.load().workspace.chroma_host/port`. Those are hardcoded in `config/settings.yaml`
as `chroma_host: chroma` / `chroma_port: 8000` — the Docker-compose service DNS name.
Provisioning a GitHub Actions service container would therefore start a Chroma nobody dials.
Wiring it for real needs either an edit to `config/settings.yaml` (a protected contract) or
new env-override plumbing in `src/config/` — both outside T-044's `folders: [".github/"]`
and beyond an S task. design.md:744's "Integration tests use a real Chroma instance
(separate Docker container in CI)" describes intent that no test implements yet.
Affects: `.github/workflows/ci.yml`, design.md:744 (intent vs. implementation gap)
Discarded: provisioning the service anyway "for future use" — an unexercised service
container is CI cost and a false signal of coverage that does not exist.
