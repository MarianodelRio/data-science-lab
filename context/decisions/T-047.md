## 2026-08-20 — T-047 [pipeline-agent]
Decided: `feature_spec.json` v2 replaces the three fixed transformation categories
(`encodings`/`null_handling`/`interactions`) with a single open-vocabulary `features` list. Each
entry is `columns` (1..N non-empty strings) / `operation` (free-form string) / `params` /
`fit_scope` (required, no default) / `rationale`, rebuilt from that whitelist so the LLM's own
object is never written through. The v1 "interactions need at least 2 columns" rule is gone: one
entry with one column and one entry with many are the same shape, so a per-column transform and an
interaction no longer need separate sections.
Why: the three categories could not express cyclical encoding, log/power transforms, datetime-part
extraction, aggregations, text length or outlier clipping — an LLM asked for them had nowhere to
put them, and either dropped them or smuggled them into `encodings` with an invented `method`.
Affects: `src/nodes/llm/feature_engineer.py`, `config/prompts/feature_engineer/v2.md`,
`config/agents/feature_engineer.yaml`, `tests/fixtures/graph_mocks.py`,
`tests/unit/nodes/llm/test_feature_engineer.py`, `docs/pipeline.md` § Design (Phase 4).
`LabState` is untouched — `feature_spec_path` stays a `str` and `_build_output_state` keeps
returning it, which T-016's `analysis_critic._detect_phase_stem` discriminator depends on.
Discarded: adding a fourth `transformations` list beside the three (two overlapping vocabularies,
and no rule for which one an LLM should reach for); a closed enum of operations (wrong by
construction for the next competition, which will need an operation nobody enumerated).
**Supersedes** both 2026-08-11 T-022 entries — the `fold_aware: true` boolean and the
single-family `_is_target_encoding_method`. T-022's third entry (`_read_eda_report` is a private
per-module copy, deliberately not shared) still stands and is unaffected.

## 2026-08-20 — T-047 [pipeline-agent]
Decided: the fit-scope guard covers six leakage-prone families — target encoding, statistical
imputation, scaling/normalization, binning/discretization, dimensionality reduction, and
frequency/count encoding. A match *requires* `fit_scope: "per_fold"`; no match means no check. The
matching mechanism is T-022's, verbatim: whole-phrase `\b...\b` regex against a separator-normalized
(`-`/`_` → space) lowercase copy, with the curated target-encoding tuple carried over unchanged.
Why: conservative asymmetry. Forcing `per_fold` on an operation that turns out to be stateless
produces identical output; missing a fitted one is a silent leak that inflates every CV score for
the rest of the run. Severity is explicitly two-tier and documented as such — target encoding leaks
the *target* and breaks CV outright, the other five leak only held-out-fold *feature* statistics —
so the uniform rejection is a stated stance, not a claim the two are the same bug. No bare stem
(`scale`, `transform`, `encoding`, `impute`, `mean`, `count`, `normalize`) is ever a keyword,
because each appears inside legitimately stateless names.
Affects: `src/nodes/llm/feature_engineer.py`, `config/prompts/feature_engineer/v2.md`.
Discarded: an allow-list of stateless operations (unbounded, and it would reject the novel
operations v2 exists to permit); inferring scope from `params` (nothing in `params` distinguishes a
fitted operation); emitting a warning instead of rejecting (nothing in the pipeline consumes
warnings — a critic-retry `ValueError` is the only feedback channel that reaches the LLM).
Note: `frequency_encoding_excluding_target_leak` — T-022's canonical false positive — is now
legitimately flagged, by the *frequency/count encoding* family. The property T-022 protected still
holds: it is not flagged as **target** encoding. It simply belongs to a family T-022 did not have,
and frequency encoding does learn global category counts.

## 2026-08-20 — T-047 [pipeline-agent]
Decided: `fit_scope`'s tokens are exactly `per_fold` and `global`, chosen to align with the
`standard_scaler_fitted_per_fold` convention `deep_learning_specialist/v1.md` already recommends
for `design.json`'s `preprocessing`. Where the two artifacts disagree, **`feature_spec.json`'s
`fit_scope` is authoritative**.
Why: T-025 deliberately kept `preprocessing` a flat `list[str]` gated by `_PREPROCESSING_STEP_RE`,
and that shape is now inherited by five landed specialists, five prompts and five test suites —
widening it to express fit timing is a separate task with its own blast radius (the T-025 discovery,
aimed at T-029). Aligning the tokens costs nothing and happens by construction; stating the tie-break
gives T-029's `coder` one source of truth instead of a judgement call at read time.
Affects: `src/nodes/llm/feature_engineer.py`, `config/prompts/feature_engineer/v2.md`,
`docs/pipeline.md`. `design.json`, `_experiment_design.py`'s `preprocessing` contract,
`_PREPROCESSING_STEP_RE` and `DESIGN_KEYS` are untouched by this task.
Discarded: widening `preprocessing` here (out of scope, and it would touch five landed specialists).

## 2026-08-20 — T-047 [pipeline-agent]
Decided: `_experiment_design._is_json_scalar` is promoted to the public `is_json_scalar` and
imported by `feature_engineer` to validate `params`, accepting a scalar **or a flat list of
scalars** — the `_validate_fixed_params` predicate verbatim. `DEGRADE_ERRORS` is adopted by both
`feature_engineer` readers, together with an `isinstance(path, str)` guard and `json.dumps` moved
inside the `try`. The **family tuples and the matcher stay private to `feature_engineer.py`**.
Why: three distinct call sites now need the same ±2**53 / non-finite check (`choices`,

plausible second (`coder`, T-029) consumes the validated *artifact*, not the validator, so T-032's
"a private shared module only when all its consumers land in the same PR" does not apply. Direction
matters too — putting feature-spec vocabulary *into* the `design.json` contract module would blur
that module's declared purpose, whereas `feature_engineer` importing two general-purpose utilities
*from* it adds no Phase-4 concept to the Phase-5 contract.
Affects: `src/nodes/llm/_experiment_design.py` (rename + docstrings only, no behavior change),
`src/nodes/llm/feature_engineer.py`.
Discarded: a fourth private copy of the scalar check; a new `src/nodes/llm/_feature_spec.py` (a
shared module for one consumer, and a stem `node_resolver._find_node_class` would have to be kept
away from); hoisting the reader helpers themselves (T-022's third decision keeps them per-module —
only the caught exception set changed).
