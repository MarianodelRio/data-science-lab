## 2026-09-14 — T-051 [Architect]
Decided: APPROVED WITH MODIFICATIONS. `LabState.score_direction` is added as a
**required** key typed `Literal["minimize", "maximize"] | None`, defaulted to `None`
in `new_state()`. Two changes to the task as written: (a) the `docs/pipeline.md`
"Done when" item is removed and handed to T-052; (b) the "set once and never
silently re-derived" Delivers bullet is reworded to a documented contract, not an
enforced one.
Why:
 - **(a) Ownership.** `docs/pipeline.md` belongs to `pipeline-agent` (CLAUDE.md §
   Module ownership); T-051 is an `infra-agent` task with `folders: [src/state.py]`.
   The "Done when" checklist as written required a write outside the assigned
   folders, violating agent rule #1. The § State passage that needs rewriting
   ("the state contract itself has no polarity field, so `score_evaluator` is
   responsible for sign-flipping") stays *operatively true* after T-051 — the field
   exists but nothing writes or reads it until T-052 — so deferring the doc edit to
   T-052 leaves no interval of incorrect documentation. T-051's documentation of
   record is the `src/state.py` module docstring, which infra-agent owns.
 - **(b) Enforceability.** `src/state.py` is a type-only module and LangGraph merges
   every non-`messages` field with a `LastValue` (last-write-wins) channel. A
   TypedDict cannot make a field write-once; `validation_config_path`'s immutability
   is likewise enforced in `ValidationStrategistNode`, not in the state contract.
   T-051 can deliver the field plus a docstring stating the contract; the enforcement
   lives in `score_evaluator` (T-052).
 - The task's premise was re-verified against `src/nodes/compute/score_evaluator.py`
   as of today (per retrospective lesson L-027): `_direction_for_metric` is still
   called fresh on every `run()` from `problem_definition.json`'s `success_metric`,
   and still defaults to `"maximize"` for an absent/unreadable file. The premise holds.
Affects: `src/state.py` (`LabState`, `new_state`), `tests/unit/test_state.py`,
`docs/adr/0004-score-polarity-on-labstate.md` (new). Downstream (T-052):
`src/nodes/compute/score_evaluator.py`, `src/nodes/compute/kaggle_client.py`,
`src/nodes/llm/error_analyst.py`, `docs/pipeline.md`.
Discarded:
 - **Adding `docs/pipeline.md` to T-051's `folders:`** — would cross a module
   ownership boundary for a doc edit that T-052 has to touch anyway, and the two
   tasks would then both edit the same § State passage.
 - **Typing the field `NotRequired[...]` instead of required-with-`None`-default** —
   `tests/unit/test_state.py::test_new_state_has_every_labstate_key` asserts
   `set(state.keys()) == set(LabState.__required_keys__)`. A `NotRequired` key drops
   out of `__required_keys__`, so a `new_state()` that forgot to set it would still
   pass that test. Required-with-`None` keeps the existing key-set test load-bearing.
 - **Also fixing `best_score=float("-inf")` in this task** — inspected and found NOT
   to be a defect. `score_evaluator` normalizes every score to higher-is-better
   (`normalized_score = raw_score if direction == "maximize" else -raw_score`) *before*
   writing `last_score`/`best_score`, so `best_score` lives in normalized space and
   `-inf` is the correct seed under both polarities. No change needed, now or in T-052.
 - **Expanding T-051 to migrate the direction readers** — three sites resolve polarity
   today; migrating them is T-052's scope and is recorded as a condition on it rather
   than pulled forward into a size-S contract task.
