## OPEN — 2026-08-18 [pipeline-agent (T-032) → pipeline-agent (whoever owns Phase 6 artifact naming)]
**The two artifact-numbering schemes inside Phase 6 can disagree.** `score_evaluator` and
`feature_importance_extractor` name their reports from
`_evaluation_common.resolve_output_iteration` — a number derived from the `exp_{N}` directory
actually read, which can differ from `state["current_iteration"]` when the state-recorded
experiment pointer is stale (that is exactly the divergence `experiment_resolution_warning`
exists to record). The three T-032 LLM nodes read and write at `state["current_iteration"]`,
because `LLMNode._resolve_output_path` does and re-deriving the directory in an LLM node was
explicitly ruled out. When the two diverge, `error_analyst` finds no
`reports/score_evaluation_{current_iteration}.json`, silently degrades all four of its inputs to
placeholders, and the whole Phase 6 LLM tail produces a content-free diagnosis. Nothing fails
loudly; the only trace is `error_diagnosis_{N}.json`'s `inputs` block being all `null`.
Required action: make the two schemes agree — either have the compute nodes also file under
`state["current_iteration"]` (and keep `iteration`/`experiment_resolution_warning` as the record of
what was actually read), or give the LLM nodes a sanctioned way to learn the resolved number
without re-deriving the directory. Not done in T-032: changing `score_evaluator`'s naming is a
contract change for a landed critical module and is outside this task's `folders:`.
Task where this should be addressed: unassigned
