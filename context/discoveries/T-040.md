## OPEN — 2026-09-13 [frontend-agent (T-040) → api-agent]
No backend endpoint exposes `LabState.experiments` or `LabState.baseline_score`
(src/state.py:39,45). The full route surface today is `POST /api/runs`,
`GET /api/runs`, `GET /api/runs/{id}`, `GET /api/runs/{id}/events` (SSE),
`WS /api/runs/{id}/chat`, `POST /api/runs/{id}/resume`, `POST /api/runs/{id}/submit`,
`GET /api/mlflow/url` — none of them return an experiments list or a baseline score;
`RunSummary` only carries a scalar `best_score`. `ExperimentsTable`
(frontend/src/components/ExperimentsTable.tsx) is built as a presentational,
fixture-driven component per its props contract (`experiments?: Experiment[]`,
`baselineScore?: number | null`), but it is inert in the running app: `Layout.tsx`
renders it with no props, so it always shows its "No experiments yet." no-data
state until a real data source exists.
Proposal: add `GET /api/runs/{run_id}/experiments` returning
`{ experiments: Experiment[], baseline_score: float | null, best_experiment_path: str }`,
read off the checkpoint via the same pattern `get_run` already uses in
src/api/routers/runs.py.

Addendum (2026-09-13, review-fix round): `ExperimentsTable` currently keys its
row list on `experiment.id` alone, with no uniqueness guarantee from the
backend contract (`LabState.experiments: list[dict]` in `src/state.py` is an
untyped list; nothing enforces unique `id`s). Harmless today since the
component is fixture-only, but once the `GET /api/runs/{run_id}/experiments`
endpoint proposed above ships and feeds real data, the endpoint should
guarantee `id` uniqueness across the `experiments` array — or, if that can't
be guaranteed server-side, a future consumer should key defensively on a
composite such as `${id}-${iteration}`.
