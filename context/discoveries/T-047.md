## OPEN — 2026-08-20 [pipeline-agent (T-047) → T-029 coder]
`design/iteration_{N}/feature_spec.json` is now schema v2: one top-level `features` list, each entry
`{columns, operation, params, fit_scope, rationale}`. Three things `coder` needs when it reads it:

1. **`fit_scope` is the authoritative fit-timing declaration.** Every entry carries it, exactly
   `"per_fold"` or `"global"`. A `per_fold` entry must be fitted **inside** the CV loop, on the
   training folds only, using the folds frozen in `validation/fold_config.json` — never fitted once
   over the whole training set and reused. `design.json`'s `preprocessing` is a flat token list with
   no notion of *when* a step is fitted (see the still-open T-025 discovery), so where a
   `preprocessing` token and a `feature_spec.json` entry describe the same step and disagree,
   **`fit_scope` wins**. Tokens were deliberately aligned so this should never actually conflict.
2. **`operation` is an open vocabulary.** There is no enum and no fixed catalogue — v2 exists
   precisely so a competition can name a transformation nobody enumerated. An operation `coder`
   does not recognize must **fail loudly**, not be silently skipped: a dropped transformation is
   invisible in the results and looks like a modeling problem rather than a missing feature.
3. **`params` values are scalars or flat lists of scalars.** Never nested objects, never lists of
   lists, never `NaN`/`Infinity`, never an integer beyond ±2**53 — all rejected at write time, so
   `coder` may rely on it.
4. **Escape column names in generated code.** [SEC-4114715b] `columns` entries are unconstrained
   free strings — validated only as non-empty, non-duplicated strings — and they originate in the
   user's own Kaggle dataset, where a header may legitimately contain a quote, a backslash, a
   newline or a `#`. They flow straight into `coder`'s codegen, so a name interpolated into a
   generated Python literal without escaping either breaks the file or changes what it means.
   Emit them with `repr()`/`json.dumps` (or index via a variable), never by string-concatenating
   into a quoted literal. This is the same class of issue as point 2 but the opposite failure
   mode: point 2 is about *not silently skipping* an unknown operation, this is about *not
   trusting* a column name's characters.
5. **There is no `schema_version` key, and that was a deliberate human ruling, not an oversight.**
   A consumer cannot distinguish a v1 file from a v2 file except by probing for the `features` key
   (v1 had `encodings`/`null_handling`/`interactions`). Adding one was considered in the T-047
   review and rejected: it would add a key to the contract `docs/pipeline.md` has just pinned and
   that T-029 will inherit. No live path breaks today — `analysis_critic` reads the artifact as raw
   text and is schema-neutral, and `resolve_feature_spec_ref` always points at the *current*
   iteration's directory — but the iteration loop means several `design/iteration_{N}/` generations
   coexist in one workspace, and a workspace resumed across a schema change could hold both shapes.
   T-029 may assume the `features` key; if it ever needs to tell the two apart, probing for
   `features` is the intended mechanism.
6. **No size or cardinality bound is enforced.** [SEC-cb459b3c] Nothing caps `len(features)`,
   `len(columns)`, `len(operation)`, `len(rationale)` or the length of a `params` list. In practice
   the node's `max_tokens: 4096` bounds all of them, and v1 had no bound either, so this is low
   risk — but `_delivery_common.MAX_INJECTED_CHARS` shows the codebase has a budget convention that
   this artifact does not follow, and the artifact is re-injected **verbatim** into
   `analysis_critic`'s prompt, so its size is someone else's context budget. Worth a bound if
   `max_tokens` ever rises or the file is ever assembled from more than one response.

## OPEN — 2026-08-20 [pipeline-agent (T-047) → whoever revisits code_critic's rubric]
Accepted residual risk in the v2 fit-scope guard, recorded so it is not mistaken for a gap nobody
noticed. `_matched_fit_scope_family` checks `operation` against six curated keyword families; an
operation matching none of them gets **no check at all** and may declare `fit_scope: "global"` even
when it is genuinely fitted. `groupby_user_mean_amount` is the canonical example — it aggregates
over other rows, so it is fitted, but it matches nothing. The vocabulary is open by design, so this
cannot be closed by adding keywords.

Two things stand above that floor. `config/prompts/feature_engineer/v2.md` states the general rule
prominently and before the family list: anything that learns a parameter, statistic, mapping,
vocabulary or basis from the data must declare `per_fold`; only a stateless row-wise transform may
declare `global`. And `code_critic`'s leakage rubric is the **only downstream check** that the
generated code actually honors each entry's declared `fit_scope` — nothing between `feature_engineer`
and the trained model re-validates it. Anyone revisiting that rubric should make the check explicit.
